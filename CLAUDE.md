# SoundLink (MusicPlayer) — Qt/C++ проект

Десктопный музыкальный плеер **SoundLink** на Qt 6.8.3 / C++23 / CMake / QML. Git-репозиторий (github.com/Stalker72742/MusicPlayer).

Код пишет один автор. Даты в шапках файлов (`Created by Stalker7274 on ...`) — ориентир по возрасту кода. Текущая версия — 0.2.

Комментарии: в `.cpp` их нет (только шапка `Created by`); всё API документируется в хэдерах doxygen-комментариями `///` на английском — `@brief` у классов и публичных членов, `@param`/`@return` где не очевидно, `///<` для полей и значений enum. Приватные детали — обычным `///` без `@brief`. `Doxyfile` в корне репозитория (`doxygen Doxyfile` → `docs/`, в `.gitignore`).

## Сборка (Windows, MinGW)

CMake-корень — `source/` (не корень репозитория). Пресет `QtMinGW` в `source/CMakeUserPresets.json`:
Qt `D:/Qt/6.8.3/mingw_64`, компиляторы `d:/Qt/Tools/mingw1310_64`, Ninja `d:/Qt/Tools/Ninja`.
После клона нужен `git submodule update --init` (QTomlUtils, QAppUpdater).

Собираются `SoundLink.exe` и `Updater.exe` (QAppUpdater). Раскладка как у установленной программы: рядом с exe только папка `bin/` — все DLL (Qt, FFmpeg, MinGW), `bin/plugins`, `bin/qml` и `bin/bin.manifest` (private side-by-side assembly, на которую ссылаются манифесты обоих exe; Qt находит плагины/QML через встроенный `qt.conf`). `bin/` раскладывается после каждой сборки `SoundLink` (`windeployqt` + генерация манифеста по факту содержимого), так что exe запускается прямо из папки сборки без Qt в PATH. Все исходники, QML-модуль и ресурсы перечислены в `source/CMakeLists.txt` — новый .cpp/.h/.qml нужно добавить туда.

Проще всего — `build-release.bat` (или `build-release.bat package`) из корня репозитория: сам переходит в `source/`, при ошибке не закрывает окно. `cmake --workflow` принимает только `--preset` (без `-S`) и ищет пресеты в текущей папке. Пресеты (в `source/`): `cmake --workflow --preset release-dist` — Release-сборка (`source/build/QtMinGW-Release`) + автономная копия в `MusicPlayer/dist`; `cmake --workflow --preset release-package` — то же + `MusicPlayer/packages/SoundLink-<версия>-win64.zip`. `dist/` и `packages/` в `.gitignore`.

Релиз: поднять `project(SoundLink VERSION ...)` → `cmake --workflow --preset release-package` → `MusicPlayer/packages/SoundLink-<версия>-win64.zip` → GitHub-релиз в `Stalker72742/MusicPlayer` с тегом `v<версия>` и этим zip. `SoundLink_deploy` — только папка `<build>/dist`. Версия пишется в одном месте (`project(VERSION)`) → `VERSIONINFO` обоих exe, `SOUNDLINK_VERSION`, `package.json`.

Тестов нет. `.clang-format` в корне репозитория (LLVM-база, Allman-скобки, отступ 4).

Известные грабли сборки:
- Release-exe — GUI-подсистема без консоли (`WIN32_EXECUTABLE` для не-Debug), Debug — с консолью для `qDebug`. В Release вывод `qDebug` никуда не идёт.
- COM/WinRT-интерфейсы, объявленные вручную, не класть в анонимный namespace: GCC при `-O2` девиртуализирует вызов в чисто виртуальный метод (переход в никуда) — так падал Release в `SystemMediaControls`. Проверять подобное только Release-сборкой.
- `windres` ломается на include-путях с пробелами (`CPP Projects`) — ресурсы exe (иконка, `VERSIONINFO`, манифест) QAppUpdater компилирует сам из своей сгенерированной папки.
- Старая `build/QtMinGW/` сконфигурирована под прежнее расположение проекта (`D:/CPP Projects/MusicPlayer`) — её нужно пересоздать.
- Индекс git хранит пути в другом регистре (`Source/Core/...`), чем на диске (`source/core/...`).

## Архитектура

### Запуск
`main.cpp`: правила логов (глушат info/debug-дампы FFmpeg из Qt Multimedia) → `QApplication` → `AppInstance` на стеке → `AppInstance::init()` → `exec()`.
`init()`: иконка приложения → `setQuitOnLastWindowClosed(false)` (закрытие окна = скрытие в трей) → `AppConfigs::RegisterAppConfigs()` → `LibrarySubsystem::Get().Initialize()` → `DownloadSubsystem::Get().Initialize()` → `QQmlApplicationEngine::loadFromModule("SoundLink", "WindowsMainWindow")` → `TrayIcon` → `SystemMediaControls` → `DiscordSubsystem::Start()` → `YtDlpSubsystem::Get().StartAutoUpdate()`, `FfmpegSubsystem::Get().EnsureInstalled()`, `DenoSubsystem::Get().EnsureInstalled()` (асинхронно) → `BrowserBridge::Get().Start()`. Если окно не загрузилось — `init()` возвращает false, приложение выходит с -1.

### `source/core/`
- `public/framework/AppInstance.h` — владелец UI: QML engine (`getEngine`, `getMainWindow`) и трей; `AppInstance::getInstance()` (nullptr вне времени жизни). Слоты `showMainWindow/hideMainWindow/toggleMainWindow`. Подсистемами не владеет.
- `public/framework/SubsystemBase.h` — подсистемы = синглтоны Мейерса через CRTP `Subsystem<T>`: `class X : public Subsystem<X>`, приватный конструктор + `friend class Subsystem<X>;`, доступ `X::Get()`. Создаются при первом `Get()` (только после `QApplication`), уничтожаются при статической деструкции — уже после `QApplication`, поэтому всё, что не должно его пережить (сеть, процессы, сохранения), освобождается в `virtual void Deinitialize()`, который вызывается по `aboutToQuit`.
- `public/framework/SystemMediaControls` — медиаклавиши и системная плашка Windows через **System Media Transport Controls** (не `RegisterHotKey`/хук: клавиши не захватываются эксклюзивно, Windows отдаёт их приложению, которое играло последним). Создаётся `AppInstance` по HWND главного окна; сессия включается только после первого проигранного трека. Интерфейсы WinRT объявлены вручную в `private/framework/SmtcInterfaces.h` (в MinGW их нет; GUID и порядок методов — из Windows SDK `winrt/windows.media.h`). Обработчик кнопок вызывается Windows из фонового потока → перекидывается в главный поток. Линкуется `runtimeobject`. На других ОС — заглушка.
- `public/framework/AppConfigs.h` — id конфигов и **все ключи настроек** (`AppConfigs::SettingsKeys`: general, library, audio, player — громкость/shuffle/repeat, online, downloads; значения-перечисления — `BrowserCookies`, `AudioQuality`), `GetAppRoot()` (= `applicationDirPath`), `GetBool/GetDouble/GetString(key)`, `RegisterAppConfigs()` (все дефолты). Конфиг `Settings`: `<appRoot>/Saved/Settings.toml` (пишутся только отличия от дефолтов; QTomlUtils сам выкидывает значения, равные дефолту), дефолты `<appRoot>/Config/DefaultSettings.toml` + код. Все настройки приложения живут здесь, других хранилищ настроек нет (данные — библиотека, плейлисты, очередь загрузок, сопряжения — в своих JSON в `<AppLocalData>`). Новая настройка: константа в `SettingsKeys` + `SetDefaultValue` в `RegisterAppConfigs()` + строка в `SettingsModel`.
- `public/subsystems/Library/` — библиотека музыки.
  - `Track.h` — трек в духе ECS: `TrackId` (стабильный между запусками) + компоненты-структуры `FileComponent` (путь/размер/mtime — пишет сканер), `TagsComponent` (теги, длительность, `bFromFile` — пишет `MetadataReader`), `StatsComponent` (дата добавления, лайк, прослушивания — пишут плеер и UI), `UserComponent` (пользовательские тэги `labels` — для умных плейлистов), `StreamComponent` (онлайн-трек: URL страницы, превью, `bSaved`). `IsOnline()` — пришёл со страницы; `HasLocalFile()` — есть файл (скан или скачанная копия онлайн-трека); `IsInLibrary()` — локальный или сохранённый онлайн-трек. **Личность трека — `TrackId`, а не источник звука**: онлайн-трек, получивший локальную копию, остаётся тем же треком (лайки, тэги, плейлисты), плеер берёт файл, а если его нет — поток. Новые данные трека — новый компонент или поле в компоненте своей «системы».
  - `LibrarySubsystem` — хранилище: плоский `QList<Track>` + индексы по id и по пути (удаление swap-remove — храните `TrackId`, не индексы). Папки — массив `AppConfigs::SettingsKeys::MusicScanFolders` в конфиге `Settings` (`GetFolders/SetFolders/AddFolder/RemoveFolder/ResetFolders`). `Initialize()` (из `AppInstance::init` до загрузки QML): грузит кэш `<AppLocalData>/library.json`, затем фоновый скан (`QtConcurrent`) → новые файлы добавляются с тегами-догадками из имени («Artist - Title», альбом = папка), изменённые и непрочитанные уходят в `MetadataReader`, пропавшие удаляются. `tracksChanged` схлопывается (≤ ~3/с), кэш пишется с задержкой 2 с и в `Deinitialize`.
    Онлайн-треки живут там же, индекс по URL страницы: `AddOnlineTrack` (найти или создать временный), `SetSaved`, `RemoveTransientTracks(keep)`; лайк онлайн-трека сохраняет его. `SetLocalFile(id, path)` — точка встраивания будущего скачивания: файл скачанной копии (трек при этом сохраняется; пустой путь — обратно к потоку; сам файл не трогается). Путь индексируется как у сканированных, так что скан папки с копией находит этот же трек и не перечитывает ему теги из файла. `SetLabels` — тэги пользователя (`labels` в кэше). Временные (результаты поиска) не попадают в списки и кэш — все потребители `GetTracks()` фильтруют по `IsInLibrary()`; сохранённые пишутся в `library.json` с полями `url`/`thumbnail` и не трогаются сканом.
  - `private/.../MetadataReader` — по одному читает теги и длительность через `QMediaPlayer` (без зависимостей), таймаут 5 с на файл.
- `public/subsystems/Online/` — онлайн-музыка через взаимозаменяемые бэкенды (`private/subsystems/Online/`, интерфейс `OnlineBackend`: `Search`, `ResolveStream`, `GetUnavailableReason`; ошибки — `OnlineError` из `OnlineTypes.h`: `Unavailable` / `Blocked` / `NotFound` / `Failed`).
  - `OnlineSubsystem` — роутер, публичный API прежний: `Search(query)` (сигналы `searchStarted/searchFinished/searchFailed`, новый поиск отменяет старый), `ResolveStream(pageUrl, context, callback)` (запросы одной страницы делят одну попытку, поток кэшируется до `expire` из URL минус 15 мин), `ReportStreamFailed(pageUrl)` (плеер: ссылка не сыграла — сброс кэша и штраф бэкенду, который её выдал), `SearchMore()` (следующая страница у того же бэкенда, что нашёл первую, без fallback; сигналы `moreResultsFinished/moreResultsFailed`), `GetBackends()`, `GetLastSearchBackend/GetLastStreamBackend`, `GuessArtistAndTitle`. Порядок: предпочтённый в настройках (`AppConfigs::SettingsKeys::OnlineSearchSource/OnlineStreamSource`), потом остальные. Недоступный пропускается сразу, `Blocked`/`Failed` — следующий, а этот 10 мин идёт последним; `NotFound` — конец.
  - `InnerTubeBackend` (`innertube`, только поиск) — POST `youtube.com/youtubei/v1/search` клиентом WEB, фильтр «только видео», язык/регион из системной локали, ~0.5 с, страница ~20 видео, следующая — по continuation-токену (`onResponseReceivedCommands[].appendContinuationItemsAction`); куки не шлются и не запоминаются. Формат ответа недокументирован — если сломается, поиск уходит в yt-dlp.
  - `YtDlpBackend` (`ytdlp`, поиск и потоки, запасной для всего) — `ytsearch20:` + `--flat-playlist --dump-single-json` (страниц нет: «ещё» перезапускает поиск с N+20 и отдаёт только новые, до 100); поток — `-f bestaudio[ext=m4a]/bestaudio/best --get-url`; всегда `--js-runtimes deno:<путь>`, если deno есть. `ResolveStreamWith(Credentials)` — PO token + visitor data (`player_client=mweb;po_token=mweb.gvs+...;player_skip=webpage,configs;visitor_data=...`) или PO token + `--cookies`. `ClassifyError` раскладывает stderr yt-dlp по видам ошибок. Каждый запуск сообщает `YtDlpSubsystem::ReportRunSuccess/Failure` (`NotFound` не считается).
  - `BrowserAssistedBackend` (`browser`, только потоки) — гибрид: у расширения берутся PO token, который настоящий плеер в браузере положил в запросы к googlevideo, и `visitorData`; дальше всё делает yt-dlp (клиент `mweb`, нужен deno). Куки — только если браузер залогинен (токен привязан к аккаунту) или голый токен упёрся в «sign in», и только при `OnlineBrowserCookies = whenNeeded` **и** включённом переключателе в расширении; пишутся во временный файл `<AppLocalData>/tmp/cookies-*.txt`, удаляются сразу после запуска (остатки чистятся при старте). yt-dlp печатает ссылку и с негодным токеном, поэтому перед отдачей поток проверяется range-запросом из середины файла.
  - `BrowserBridge` — связь с расширением: `QWebSocketServer` только на 127.0.0.1, первый свободный порт из 47821–47825 (тот же список в `extension/background.js`). Безопасность: Origin только `chrome-extension://` / `moz-extension://` (проверяется ещё в handshake); не больше 6 соединений, из них 3 несопряжённых; hello за 10 с; сообщения до 1 МБ, только текст; сопряжение — 6-значный код в приложении (живёт 10 мин, 5 попыток на соединение, потом новый код), вводится в попапе расширения, в ответ случайный токен 32 байта; хранятся только SHA-256 хэши (`<AppLocalData>/browser-bridge.json`); до сопряжения расширению ничего не отправляется. `Request(method, params, context, callback)` — запрос к самому свежему сопряжённому расширению (методы `credentials`, `cookies`), таймаут 10 с. `ForgetPairedBrowsers()`.
- `public/subsystems/YtDlp/DenoSubsystem` — JS-рантайм для yt-dlp: без него YouTube-извлечение устарело (только клиент `visionos`) и PO token не применить. Ставит deno из релизов denoland/deno (`*.zip` + `*.zip.sha256sum` в формате PowerShell `Get-FileHash` — его понимает `ReleaseAssetDownload`) в `<AppLocalData>/tools` рядом с yt-dlp. Не обновляется.
- `public/subsystems/Discord/DiscordSubsystem` — Discord Rich Presence без SDK: локальный pipe `\\.\pipe\discord-ipc-0..9` (`QLocalSocket`, асинхронно, перебор номеров), кадры `[opcode u32 LE][длина u32 LE][JSON]`, handshake с id приложения `1556337315482173460` (его имя в Developer Portal — то, что Discord пишет в «Listening to»), после `READY` — `SET_ACTIVITY`: type 2 (Listening), `status_display_type` 2 (в статусе — название трека), details = название, state = исполнитель (+ «· Paused»), `timestamps` start/end в мс (прогресс-бар; при паузе их нет), для онлайн-треков — обложка (https-URL в `large_image`) и кнопка «Open on YouTube». Следит за `PlayerSubsystem` сам после `Start()` (из `AppInstance::init`); Discord не запущен — повторный поиск pipe раз в 20 с. Лимит Discord ~5 обновлений за 20 с: обновления схлопываются (не чаще раза в 4 с), одинаковые (без учёта дрейфа часов) не шлются, перемотка распознаётся по сдвигу старта > 2 с. Выключается настройкой `general.discordPresence` (`ApplySetting`: отключение от pipe убирает статус).
- `public/subsystems/Downloads/DownloadSubsystem` — очередь скачивания онлайн-треков (до 2 одновременно): `Enqueue(tracks)` (только онлайн без локальной копии; результат поиска сохраняется в библиотеку, `Cancel` это откатывает), `Cancel`, `Retry`, `ClearFinished`, `RemoveDownload` (удаляет файл, трек снова стримится). yt-dlp (`-f bestaudio[ext=m4a]/bestaudio/best`, `--embed-metadata` при ffmpeg, deno) качает в `<AppLocalData>/downloads-tmp/<id>.<ext>`, прогресс — строки `--progress-template "download:SLPROGRESS ..."`, итоговый путь — `--print after_move:filepath`; затем файл переносится в папку загрузок (`AppConfigs::SettingsKeys::DownloadFolder`, по умолчанию `<Music>/SoundLink` — внутри папки скана) как «Artist - Title.m4a» без перезаписи и становится копией трека через `LibrarySubsystem::SetLocalFile`. Зависание без вывода 2 мин — ошибка. Незавершённые задания — в `<AppLocalData>/downloads.json`, продолжаются после перезапуска.
- `public/subsystems/Playlists/PlaylistSubsystem` — плейлисты в `<AppLocalData>/playlists.json` (запись с задержкой 1 с и в `Deinitialize`). `Playlist`: статический (`tracks` — TrackId в порядке пользователя; `AddTracks` сохраняет временные онлайн-треки, `MoveTrack`) или умный (`rules` — `PlaylistRule{field, op, value}` строками, `bMatchAll`, `sort`, `limit`, `excluded` — скрытые пользователем). `RemoveTracks`: из статического удаляет, в умном скрывает (`RestoreExcluded`). `Resolve(id)` — треки к показу (умные считаются по библиотеке сейчас; ушедшие из библиотеки пропускаются, но не забываются), `Evaluate(...)` — для превью. Поля правил — `GetRuleFields()` (artist, title, album, genre, tag, year, duration в минутах, playCount, liked, source = local/youtube/downloaded, added/played за N дней), операторы по типу поля — `GetOperators`, сортировки — `GetSortOrders`. Новое поле — там и в `Matches`. `ForgetTrack` — трек ушёл из библиотеки (зовёт `LibraryViewModel::setInLibrary(false)`).
- `public/subsystems/Player/PlayerSubsystem` — проигрывание через `QMediaPlayer` + `QAudioOutput` (есть локальный файл — играет его; иначе онлайн-трек — сначала `OnlineSubsystem::ResolveStream`, на это время `IsLoading()`, а `IsPlaying()` значит «заиграет после загрузки»; ошибка плеера на онлайн-треке один раз перерезолвит поток и продолжит с той же позиции; устаревшие ответы отсекаются счётчиком `loadRequest`): очередь из `TrackId` (`PlayQueue`), `Play/Pause/TogglePlay/Next/Previous/Seek`, громкость 0..1 в логарифмической шкале, shuffle, `RepeatMode` `Off/All/One` (все три сохраняются в конфиг и восстанавливаются; громкость — с задержкой 0.5 с и округлением до сотых), устройство вывода (`ApplyOutputDevice`: из настройки, иначе системное по умолчанию, следит за подключением устройств) (One — только при естественном конце трека); конец трека → `Next()`, в конце очереди без повтора — `stop()` на последнем треке; при старте трека — `LibrarySubsystem::MarkPlayed`, точная длительность — `SetDuration`.
- `public/subsystems/YtDlp/YtDlpSubsystem` — держит yt-dlp установленным и свежим: официальный standalone-бинарник (Python внутри, зависимостей нет) из релизов github.com/yt-dlp/yt-dlp с проверкой по `SHA2-256SUMS`, ставится в `<AppLocalData>/tools` (`%LOCALAPPDATA%/SoundLink/tools`). `GetExecutablePath()` — управляемая копия, иначе yt-dlp из PATH. `CheckForUpdates()`, `InstallLatest()`, `EnsureLatest()`; последняя версия — GitHub API `releases/latest`, локальная — `yt-dlp --version`. `StartAutoUpdate()` — проверка сразу и раз в час. Каждый запуск yt-dlp обязан сообщить результат: `ReportRunFailure()` запускает `EnsureLatest()` (первый раз сразу, каждый следующий не раньше чем через N минут после предыдущего, N — число таких проверок), `ReportRunSuccess()` сбрасывает кулдаун. Сигналы `stateChanged`, `downloadProgress`, `errorOccurred`; свойства `state/localVersion/latestVersion` (под будущий QML).
- `public/subsystems/YtDlp/FfmpegSubsystem` — ставит ffmpeg для yt-dlp, если его нет: сборка yt-dlp/FFmpeg-Builds (`*-gpl-shared.zip`, проверка по `checksums.sha256`), распаковка системным `System32/tar.exe` (Windows 10 1803+), в `<AppLocalData>/tools/ffmpeg`. `GetLocation()` — папка с ffmpeg (управляемая, иначе из PATH) для `--ffmpeg-location`. Не обновляется.
- `private/subsystems/YtDlp/ReleaseAssetDownload` — общий хелпер: потоковое скачивание ассета релиза GitHub в файл с проверкой SHA-256 по файлу сумм.

`.cpp` лежат в `private/`, хэдеры публичного API — в `public/`.

### Конфиги — QTomlUtils
Внешняя либа, git submodule `third_party/QTomlUtils` (https://github.com/Stalker72742/QTomlUtils, API в её `README.md`), собирается статически. Include — `<QTomlUtils/QTomlUtils.h>`. Кратко: `RegisterConfig(id, path, defaultsPath)`, `FindPropertyValue<T>(id, "a.b", default)`, `SetPropertyValue`, `SetDefaultValue`, `ResetToDefault`; пользовательский файл хранит только отличия от дефолтов, как в UE. ### Обновления — QAppUpdater
Git submodule `third_party/QAppUpdater` (https://github.com/Stalker72742/QAppUpdater, документация в его `README.md`), подключён `qau_setup(SoundLink ...)` в `source/CMakeLists.txt` (репозиторий релизов, иконка, `PROTECTED_PATHS Saved`, `QML_DIR`). Даёт `Updater.exe` (окно + CLI: `--check`, `--update`, `--path <папка|zip>`, `--install`), `bin/`-раскладку, `VERSIONINFO`, цели `SoundLink_deploy`/`SoundLink_package` и `QAppUpdater::Core` для приложения. В приложении: `main` удаляет «хвосты» прошлого обновления (`InstallLayout::removeLeftovers`), `AppInstance` создаёт `AppControlServer` до загрузки QML (`getControlServer()`; апдейтер через него просит приложение закрыться → `quit`), `AppInfoViewModel` проверяет релиз в процессе (`ReleaseFinder`, настройки из `updater.json`) и ставит обновление **без окна апдейтера**: `installUpdate` → `--update --report`, `installFromPath` → `--path ... --update --force --report` (окно — только `openUpdater`). С `--report` апдейтер шлёт в `AppControlServer` строки `status {stage, done, total}` и `result {ok, message}` → сигналы `updaterStatus` / `updaterFinished` → состояние `Installing` (этап, прогресс) или `InstallFailed`; 60 с тишины — тоже ошибка (апдейтер не запустился или старый). Закрыв приложение, установщик пишет итог в `update/result.json` и перезапускает приложение даже после отката; приложение читает его при старте (`InstallLayout::takeUpdateResult` → `lastResultText` на экране Updates). Пользовательские данные, которые апдейтер не трогает: `Saved/`, `logs/`, `update/`, `updater.json`. Правки либы — в submodule: коммит, пуш, тег, затем коммит указателя в MusicPlayer.

### Расширение браузера — `extension/`
MV3, один код для Chrome и Firefox 128+ (`background.service_worker` и `background.scripts` одновременно). Ставится unpacked: кнопка «Open extension folder» в Settings › Online (файлы вшиты в ресурсы приложения — `qt_add_resources(... "extension")` в `source/CMakeLists.txt`, новый файл расширения добавлять туда же). `background.js` — ищет приложение по портам с backoff (будильник раз в минуту будит уснувший service worker), ping раз в 20 с, сопряжение, ответы на `credentials` / `cookies`; PO token ловит `webRequest` в запросах к `googlevideo.com/videoplayback`: параметр `pot` в URL или, для SABR (десктопный веб-плеер получает только `serverAbrStreamingUrl`, без ссылок на форматы), protobuf-тело POST — `VideoPlaybackAbrRequest.streamer_context` (19) → `StreamerContext.po_token` (2), base64url. `page.js` (MAIN world на youtube.com) читает `ytcfg`: visitorData из `INNERTUBE_CONTEXT.client.visitorData` (ключа `VISITOR_DATA` больше нет), `LOGGED_IN` → `relay.js` → background. В `manifest.json` свой CSP без `upgrade-insecure-requests`: дефолтный CSP Firefox MV3 его содержит и превращает `ws://127.0.0.1` в `wss://` — расширение тогда не видит приложение (в логе приложения: «failed the WebSocket handshake»). `popup.html/js` — статус, ввод кода, переключатель «Share YouTube cookies when needed» (по умолчанию выкл.). Токена нет, пока в браузере не проиграно хоть одно видео.

## Текущее состояние
Работает: запуск, навигация по экранам, главная, поиск с подсказками и тэгами, трей, конфиги, автоустановка и обновление yt-dlp, автоустановка ffmpeg, проигрывание локальной библиотеки, статус в Discord, статические и умные плейлисты (с перетаскиванием), тэги треков, очередь скачивания, повтор Off/All/One, YouTube-поиск (InnerTube, запасной — yt-dlp) и стриминг (расширение браузера + yt-dlp, запасной — yt-dlp) с сохранением в библиотеку (❤ или «Add to library»). Мост к расширению проверен фальшивым клиентом; с настоящим браузером и настоящим PO token — ещё нет.
